# نهمینو — بسته آماده اتصال حافظه و AI

این بسته، نسخهٔ آمادهٔ استقرار روی **Cloudflare Pages** است. صفحات، طراحی و ناوبری کار می‌کنند، اما **تا اجرای SQL و تنظیم Supabase، ثبت نام و آپلود واقعی فعال نیستند**؛ و تا تنظیم Gemini، استودیوی AI فعال نمی‌شود. آزمون/نمره‌ها در این نسخه هنوز دادهٔ محلی نمایشی دارند و برای امتحان رسمی/نمایش عمومی نمره قابل استفاده نیستند.

## ۱. آپدیت بدون پاک‌کردن سایت
محتویات ZIP را استخراج کنید. **فایل‌ها و پوشه‌های درون بسته** را در شاخهٔ اصلی مخزن GitHub متصل به Pages قرار دهید (نه خود ZIP). پوشهٔ `functions/api` را حتماً با ساختار خودش نگه دارید. Cloudflare Pages: Framework `None`, Build command خالی, Output directory `.`. GitHub Commit انتشار جدید را شروع می‌کند.

## ۲. فعال‌سازی حافظه Supabase
اگر دیتابیس پروژه خالی است، محتویات `schema.sql` را در **Supabase > SQL Editor** اجرا کنید. اگر قبلاً جداول نسخه‌های پیشین را ساخته‌اید، این فایل *migration* نیست؛ بدون بررسی مجدد روی دیتابیس موجود اجرا نکنید. برای آن باید migration سازگار تهیه شود.

در Supabase > Project Settings > API، `Project URL` و **anon legacy key** را بردارید؛ مقادیر این دو را در `config.js` قرار دهید. این دو عمومی‌اند، اما کلید `service_role` محرمانه است و باید صرفاً در Cloudflare قرار گیرد.

در **Cloudflare Pages > Settings > Variables and Secrets > Production** این چهار متغیر را وارد کنید:
- `SUPABASE_URL` ← آدرس پروژه
- `SUPABASE_ANON_KEY` ← anon key
- `SUPABASE_SERVICE_ROLE_KEY` ← کلید service_role؛ **Secret**
- `GEMINI_API_KEY` ← کلید Gemini که از قبل تهیه شده؛ **Secret**

سپس سایت را Redeploy کنید. هیچ‌یک از Secretها را در GitHub/چت قرار ندهید.

## ۳. ثبت نام بدون ایمیل
در سایت کاربران فقط **نام کاربری انگلیسی** (۳ تا ۲۵ نویسه) و **رمز حداقل ۸ نویسه** وارد می‌کنند. سرویس حساب از شناسه ایمیل فنی داخلی استفاده می‌کند؛ ایمیل واقعی کاربران را جمع‌آوری نمی‌کند. در این نمونه بازیابی رمز خودکار وجود ندارد. برای استفاده در مدرسه، قبل از انتشار عمومی ثبت نام، باید ضدربات، محدودسازی نرخ و بازیابی رمز طراحی شود.

## ۴. مدیر کل
برای امنیت، رمز مدیری که در چت عنوان شده **در فایل‌ها کدنویسی نشده** است. ابتدا با نام کاربری دلخواه و رمز جدید حساب بسازید. سپس در Supabase > Authentication > Users، UUID آن حساب را پیدا کنید و در SQL Editor پس از جایگزینی UUID اجرا کنید:

```sql
update public.profiles set role = 'admin' where id = 'YOUR_USER_UUID';
```

بعد از خروج و ورود دوباره، صفحهٔ مدیریت فعال می‌شود. هر ثبت‌نام معمولی نقش `student` دارد. **هیچ کاربری صرفاً با واردکردن رمز مدیر به نقش مدیر تبدیل نمی‌شود**.

## ۵. آپلود فایل
مدیر پس از ورود می‌تواند برای هر درس و بخش (سؤالات متن، نمونه سؤال، جزوه، مشق، جزوات خاص) مطلب و چند پیوست بارگذاری کند. فرمت‌ها: PDF، JPG/PNG/WebP/GIF، MP4/WebM، DOC/DOCX، PPT/PPTX، TXT/CSV/MD/JSON. حداکثر هر فایل ۲۰ مگابایت و سقف واقعی فضای رایگان Supabase نیز برقرار است. PDF، عکس و ویدئو درون صفحه نمایش داده می‌شوند. `learning-files` عمومی است؛ **هیچ فایل خصوصی یا پاسخنامه محرمانه‌ای در این bucket نگذارید**.

## ۶. Gemini و پایان راه‌اندازی
تابع `functions/api/ai.js` یک مسیر سروری `/api/ai` دارد. با احراز هویت مدیر، متغیرهای بالا و مدل رایگان قابل دسترس می‌تواند درخواست‌های تولید جزوه/سؤال دریافت کند. سهمیه نمونه ۱۰ درخواست در روز برای مدیر است (محدودیت واقعی Gemini ممکن است متفاوت باشد). **اجرای واقعی روی حساب شما از اینجا آزمایش نشده است**.

### چک‌لیست مرحله پایانی
- [ ] پس از Redeploy، صفحهٔ سایت بدون خطا باز می‌شود
- [ ] SQL روی پروژه Supabase با موفقیت اجرا شده
- [ ] ثبت‌نام/ورود نام کاربری در دو مرورگر تست شده
- [ ] نقش مدیر به UUID درست اختصاص داده شده
- [ ] یک PDF و یک عکس توسط مدیر بارگذاری و روی دستگاه دوم دیده شده
- [ ] در Network، درخواست `/api/ai` به‌جای 404 پاسخ درست می‌دهد
- [ ] درخواست جزوه/سؤال Gemini با اطلاعات غیرشخصی تست شده

**محدودیت مهم:** آزمون و رتبه‌بندی چندکاربره هنوز در مرورگر نگهداری می‌شود؛ برای پایان واقعی پروژهٔ مدرسه باید ذخیره امتحان، کلید پاسخ و تصحیح، و نمرات به SQL/RPC امن Supabase متصل شود. از این بخش برای آزمون رسمی استفاده نکنید.
