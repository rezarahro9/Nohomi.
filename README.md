# نهمینو ۳ — نسخه استقرار Cloudflare Pages

## آنچه همین حالا کار می‌کند
- ظاهر فارسی روان و واکنش‌گرا، ۱۰ درس و ۵ بخش برای هر درس
- مطالب و پیوست با لینک (محلی؛ فقط در همان مرورگر)
- ساخت پیش‌نویس آزمون چهارگزینه‌ای و تشریحی، انتشار توسط نقش مدیر در *پیش‌نمایش محلی*
- برگزاری آزمون، تصحیح تستی و توضیح کلید پاسخ، گزارش و رتبه‌بندی نمایشی
- رابط ساخت جزوه، تبدیل سؤال و آزمون از متن یا عکس (JPG/PNG/WebP، تا ۴ مگابایت)

## محدودیت مهم نسخه اولیه
داده‌های محتوا/نمره/آزمون هنوز **در localStorage مرورگر هستند**، پس بین دستگاه‌ها مشترک نیستند. انتخاب نقش در حالت پیش‌نمایش امن نیست و در نسخه عمومی به کاربر اعتماد نمی‌شود. کلید سؤال‌های آزمون‌های نمایشی نیز در مرورگر است: **برای آزمون واقعی استفاده نکنید**. عکس امتحان در API فرستاده می‌شود و برای حفظ حریم خصوصی فقط از منابع بدون داده شخصی استفاده کنید.

## استقرار (چیدمان فایل‌ها را حفظ کنید)
ریشه مخزن GitHub باید شامل `index.html`, `config.js`, `schema.sql`, `functions/api/ai.js` باشد. پروژه Cloudflare Pages را با Framework None و Build output `.` و Build command خالی نگه دارید. Git Commit خودکار نسخه تازه را منتشر می‌کند.

## اتصال واقعی Gemini (امن، مدیر-محور)
1. در Supabase SQL Editor فایل `schema.sql` را اجرا کنید. این SQL برای زیرساخت نسخه سروری است و جایگزین کامل ذخیره محلی صفحات فعلی نمی‌شود.
2. در Supabase، از Project Settings > API آدرس پروژه و publishable/anon key را در `config.js` قرار دهید (این دو عمومی‌اند). **هرگز service_role را اینجا قرار ندهید.**
3. در Cloudflare Pages > Settings > Variables and Secrets مقادیر سروری `GEMINI_API_KEY`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` را اضافه کنید. مقدار `SUPABASE_SERVICE_ROLE_KEY` را Secret بگذارید و هرگز در GitHub قرار ندهید. کلید Gemini هم Secret باشد.
4. در Supabase Auth یک حساب ایمیل/گذرواژه بسازید. نقش پیش‌فرض student است. فقط بعد از تایید هویت مدیر، در SQL Editor به صورت دستی آن حساب را `admin` کنید: `update public.profiles set role='admin' where id=(select id from auth.users where email='YOUR_ADMIN_EMAIL');`.
5. پس از فعال‌شدن config.js، ورود امن ظاهر می‌شود. وارد حساب مدیر شوید و در بخش AI درخواست بفرستید. تابع `/api/ai` توکن را با Supabase اعتبارسنجی می‌کند و نقش admin را روی سرور کنترل می‌کند. روزانه حداکثر ۱۰ درخواست برای هر مدیر در جدول `ai_usage` محاسبه می‌شود (در مجموع سهمیه Gemini ممکن است زودتر تمام شود).
6. کلید Gemini فقط در سرور نگهداری شود؛ ثبت متغیر جدید ممکن است نیاز به Redeploy داشته باشد.

## قبل از استفاده واقعی در مدرسه
باید اطلاعات مطالب، آزمون‌ها، کلید پاسخ و نتایج از localStorage به Supabase منتقل شوند، RLS و submit/grading کاملاً سروری شوند، جداسازی کلاس‌ها و حریم خصوصی نمرات پیاده‌سازی شود و رضایت مناسب برای نمایش نام/نمره دانش‌آموزان گرفته شود. اکنون این بخش‌ها **نسخه نمایشی** هستند، نه سامانه آماده آزمون محرمانه.

راه‌اندازی Gemini بدون پرداخت به سهمیه رایگان گوگل و دسترسی منطقه‌ای/مدل انتخابی بستگی دارد؛ استفاده نامحدود تضمین نمی‌شود.
